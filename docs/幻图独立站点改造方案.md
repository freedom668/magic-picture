# 幻图独立站点改造方案

> 目标：在**轻度重做前端**的前提下，把当前项目独立成「幻图网站」，与之前的 Toonflow 在运行、数据、标识、上游四个层面互不干扰。先在本机 Windows 落地，再谈部署。
>
> 本文只给方案，不含代码改动。带「待拍板」的需要你确认后我才动手。

---

## 一、先校准一个前提

当前仓库 `d:/toonflow-app` **本身就是幻图，不是原版 Toonflow**。依据：

| 事实 | 位置 |
| --- | --- |
| 根 `package.json` 的 `name` 已是 `magic-picture`，描述为「幻图 Magic Picture」 | `package.json` |
| 页面标题已是「幻图 Magic Picture」 | `apps/web/index.html` |
| 品牌词在翻译出口统一替换 | `packages/i18n/src/index.ts` |
| Logo 已换成自绘图形，原件备份为 `logo-toonflow-backup.svg` | `packages/assets/` |
| 遥测已断，`local` 渠道让官方接口返回 503 | `apps/web/src/lib/anonymousData.ts`、`apps/server/src/utils/channel/index.ts` |
| 首页 GitHub 链接已指向 `freedom668/magic-picture` | `apps/web/src/pages/home/index.vue:43` |
| Git 仅一次提交 `8fc7cef 初始化幻图 Magic Picture`，工作区干净 | — |

所以「独立」不是把 Toonflow 改造成幻图（已完成），而是解决剩下三件事：

1. **运行隔离** —— 同机上还能不能同时跑原版 Toonflow，两者不抢端口、不抢数据、不抢计划任务。
2. **前端完成度** —— 现在的品牌是「显示层打补丁」，不是源头改造，看得见的地方还留原味。
3. **可交付性** —— 目录、启动方式、构建产物是不是一个能独立搬走的整体。

## 二、隔离的五个维度（含实测结论）

### 1. 进程与端口

| 项 | 现状 | 结论 |
| --- | --- | --- |
| 服务端口 | `TOONFLOW_SERVER_PORT`，默认 `3000` | 已可通过环境变量改，**无需改代码** |
| 前端 dev 代理 | 读同一个变量 | 已联动，无需改代码 |
| 多租户创作网关 | `creationPort = 10888` **硬编码** | 若启用多租户，必须改成可配置；不启用则无影响 |

**建议**：幻图固定 `3100`，原 Toonflow 保持 `3000`。改 `start-toonflow.bat` 里的 `set` 一行即可。

### 2. 数据目录（最容易被忽略的一处坑）

服务端数据目录解析顺序：

- `TOONFLOW_DATA_DIR` 环境变量优先
- 否则 `<应用根>/data`（源码运行时是仓库根，构建后是 `build/server` 的上两级）

**坑在这里**：三个插件脚手架把同步目录写死在仓库 `data/` 下，与 `TOONFLOW_DATA_DIR` 无关：

| 文件 | 硬编码 |
| --- | --- |
| `packages/nodeScaffold/index.ts:56` | `../../data/nodes` |
| `packages/toolScaffold/index.ts:46` | `../../data/tools` |
| `packages/extScaffold/index.ts:36` | `../../data/ext` |

结果是：一旦把数据目录指到别处，`bun run dev:plugins` 仍然往旧位置同步，新站点看不到插件，表现为「节点列表为空、工具全丢」，且不报错。**这是本次改造必须处理的第一个真实缺陷。**

两条路，选一条：
- A（省事）：数据目录就用仓库内的 `data/`，靠「换整个目录」来隔离。
- B（干净）：给三个脚手架加 `TOONFLOW_DATA_DIR` 支持，数据目录可外置。改动约 3 个文件，收益是站点可以整体搬走。

### 3. 浏览器侧存储

- `localStorage` 的 persist key 是 `toonflow.projectList`、`toonflow.developer` 等。
- 浏览器按 **origin（协议+主机+端口）** 隔离，所以 `3100` 与 `3000` 天然互不干扰，**当前无需改 key**。
- 但**将来若用同一域名不同路径反向代理**（如 `/` 与 `/toonflow`），origin 相同 → 项目列表、开发者标记会互相覆盖。那时必须加 key 前缀。

### 4. 系统标识

| 项 | 现状 | 处理 |
| --- | --- | --- |
| 计划任务名 | `ToonflowWeb` | 改名为 `MagicPictureWeb`，避免与原版互相 Start/Stop |
| 启动脚本 | `start-toonflow.bat` | 改名并同步端口、渠道变量 |
| 桌面协议 | `toonflow://` | 仅桌面端注册；本项目按 Web 站点运行，暂不涉及 |
| favicon | **不存在**，`index.html` 里没有 icon 链接 | 需补，否则浏览器显示默认地球图标 |

### 5. 上游同步

包名 `@toonflow/*` 约 667 处，交接文档已明确「不改，改了会引发全量引用错误」。这意味着：

- **包名层面的独立做不到**，也不该做。
- 真正的上游隔离是 Git 层：当前仓库是干净 fork，不要 `git remote` 拉上游 master 直接 merge。上游有新版本时，用 `git diff` 挑要的提交，避免覆盖你的品牌改动。

## 三、前端「轻度重做」的边界

按风险从低到高分三层，建议只做 L1、L2 中你真正在意的部分。

### L1 门面（建议做，1–2 天）

| 落点 | 文件 | 说明 |
| --- | --- | --- |
| 首页 | `apps/web/src/pages/home/index.vue` | 侧栏品牌、`今天要做点什么？` 主区、创建卡片 |
| 引导页 | `apps/web/src/pages/hello/index.vue` + `bg.vue` | 首次启动的「快速开始」，双栏 + 胶片背景 |
| 关于页 | `apps/web/src/components/settings/panels/about/index.vue` | 含原项目出处的合规声明，**建议保留** |
| 主题 | `apps/web/src/lib/appearance.ts` | 主色、圆角、字号已是变量驱动，改默认值即可全局生效 |
| favicon | `apps/web/index.html` | 需新增 |

### L2 应用外壳（可选，2–3 天）

工作区顶部/侧栏、设置面板分组。文件集中在 `apps/web/src/pages/workspace/index.vue`、`apps/web/src/components/settings/`。

风险：这些是高频操作区，改动容易碰坏快捷键、拖拽、面板切换。**建议放到 L1 稳定之后再做。**

### L3 编辑器内部（不建议动）

`pages/workspace/panels/canvas/`（16 vue + 11 ts）是 Vue Flow 画布与节点交互核心，另有 `patches/vueFlowCore.patch` 补丁。此处改动收益低、回归成本高。

### 关于「品牌替换」这件事

现在的做法是在 `translate()` 出口正则替换 `Toonflow → 幻图`。优点是**一处改、21 语言全覆盖**；代价是：

- 源码里搜不到「幻图」，新人接手会困惑；
- 个别拼装文案可能替换后不通顺；
- 无法做「同一处文案，中英文品牌名不同」这类精细控制。

**建议**：L1 重做 UI 时，把**你实际要出现品牌的固定位置**改成直接写 `幻图`，其余继续走替换。不做 21 个语言包的全量清洗——那是纯体力活且收益接近零。

## 四、分阶段计划

| 阶段 | 内容 | 产物 | 预估 |
| --- | --- | --- | --- |
| **P0 隔离骨架** | 端口 3100、计划任务与 bat 改名、favicon、确认插件同步目录策略 | 幻图能与原版同机并存 | 半天 |
| **P1 门面重做** | 首页、引导页、关于页、主题默认值 | 打开就是「幻图」而不是「改过名的工作台」 | 1–2 天 |
| **P2 品牌收口** | 定点文案直写、清理显示层补丁的边角 | 源码可读、无「补丁感」 | 1 天 |
| **P3 上线准备** | 鉴权、HTTPS、反向代理、备份 | 可对外 | 部署阶段单独评估 |

P0 完成即可日常使用；P1 是本轮的主要交付；P2、P3 按需。

## 五、风险清单

1. **插件同步目录**（前述）：换数据目录后插件不跟随，且无报错。P0 必须验证。
2. **构建清空**：`vite build` 会清空 `build/web`；之前记录的「文件数量保护导致构建失败」需留意，必要时先移走目录再构建。
3. **不要顺手解除多租户屏障**：`apps/web/src/components/settings/panels/multiTenant/developmentNotice.vue` 目前是「正在开发」静态页，交接文档明确要求不得因其他任务解除。若将来要做 SaaS，那是独立立项。
4. **多租户 10888**：一旦启用会占用固定端口，与同机其他实例冲突。当前不启用，无需处理。
5. **MIT 合规**：`LICENSE` 中 `Copyright (c) 2026 HBAI-Ltd` 必须保留，关于页保留原项目出处。
6. **不要动 `@toonflow/*` 包名**：667 处引用，改动收益为零、破坏面极大。
7. **`data/` 不可提交**：仓库根 `data/` 必须在 `.gitignore` 内，含 API Key。

## 六、需要你拍板的三件事

1. **原版 Toonflow 现在还在这台机器上跑吗？**
   - 在跑 → 端口必须换（建议 3100），计划任务要改名，两份数据目录彻底分开。
   - 不跑 → 隔离压力小，但建议仍改端口，为将来并存留余地。

2. **「独立出来」是指哪个动作？**
   - (a) 就在 `d:/toonflow-app` 继续演进，只做运行时隔离；
   - (b) 复制到新目录（如 `D:/magic-picture`）+ 新建独立 Git 仓库，本项目作为交付物；
   - (c) 保留当前目录开发，另建一个只放构建产物的运行目录（推荐：源码与运行分离，改代码不受运行中文件占用影响）。

3. **前端视觉方向**：沿用现在的深色 + 渐变风格做精修，还是要一套全新视觉（配色、圆角、字体）？这决定 P1 的工作量是「调参数」还是「重画」。

P0 具体动作（不含 UI）：

1. 在启动脚本与计划任务中把端口固化为 `3100`，任务名改 `MagicPictureWeb`；

4. 不做任何删除、不迁移原数据，验证通过后交给你手动切换。
